# Phase 2.5 — Legacy Triage Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the 23 records in `seed/legacy/2025-26-aistudio.json` into real `schools`/`programs`/`application_cycles` rows plus their provenance (`sources`/`claims`), following the legacy-data rules in `CLAUDE.md`: only `name`/`city`/`state`/`credential`/`website_url` enter as `state='known'`; every GPA, deadline, tuition, and class-size figure enters as `state='unknown'` with the legacy number preserved as a `claims.note` hint, never in a value column. No UI — this is a script.

**Architecture:** Three pure/impure layers, mirroring the separation `docs/plan.md` §3 describes for the future `src/domain/import/diff.ts`: a Zod schema validates the raw JSON (`scripts/legacy-import/schema.ts`), a pure transform (`scripts/legacy-import/transform.ts`, no DB handle, fully unit-testable) turns each validated record into a fully-worked-out `ProgramImportPlan`, and a DB-applying module (`scripts/legacy-import/apply.ts`) walks those plans inside one `db.transaction(...)` call, either committing (`--apply`) or throwing a sentinel to force a rollback (dry run, the default). A thin CLI (`scripts/import-legacy.ts`) wires the three together and prints a report.

**Tech Stack:** drizzle-orm 0.45.2, better-sqlite3 13.0.3, zod 4.4.3, tsx 4.23.12 — all already installed, all already used by Phase 2's schema/client/migrate modules, which this plan reuses unmodified.

**Spec:** `docs/plan.md` §8–9 (legacy corpus quality assessment, Phase 2.5 gate), `docs/research-workflow.md` §8 (per-program triage procedure, known special cases), `docs/data-model.md` (schema this import writes into), `CLAUDE.md`'s "Legacy data" and "Import rules" sections, and `seed/legacy/2025-26-aistudio.json` itself (the 23 records, read in full while writing this plan).

## Global Constraints

- npm is the package manager (`CLAUDE.md`).
- Legacy numbers and dates import as `state='unknown'` with the old value kept in `claims.note`. Only name, city, credential, and URL import as `state='known'`. Never import legacy data as `verified` (`CLAUDE.md`).
- Imports are dry-run by default; `--apply` is required to write (`CLAUDE.md`). An apply runs in one transaction; there is no partial mode. Running the same bundle twice must report zero changes (`CLAUDE.md`).
- Zod validates all external input, including import bundles (`CLAUDE.md`) — the legacy JSON is external input.
- Calendar dates are `TEXT` `YYYY-MM-DD`, never epoch timestamps; `checked_at`/audit instants are `INTEGER` epoch ms (`docs/data-model.md` §7) — not directly exercised here since every claim this import writes has `checked_at = NULL` (verification stays `draft`), but binding for any date column touched.
- `programs.legacy_key` is the idempotency key for this import — it stores the exact legacy `name` string and is nullable, write-once (`docs/data-model.md` §3).
- Canonical data is soft-deleted via `status='archived'`, never hard-deleted (`CLAUDE.md`) — not exercised by this import (nothing is deleted), noted because the report-building code must never call `.delete()`.
- `src/db/**` does not import `server-only` — a Task 4 ruling from the Phase 2 plan removed it project-wide because it throws unconditionally when loaded outside Next's bundler (`tsx`, Vitest, `drizzle-kit`). Nothing in this plan reintroduces it.
- Reuse Phase 2's `src/db/client.ts`, `src/db/pragmas.ts`, `src/db/migrate.ts`, and `src/db/schema/**` as-is. Do not modify them.

## API notes (verified against installed packages, not memory)

- `db.transaction<T>(transaction: (tx) => T, config?): T` (`node_modules/drizzle-orm/better-sqlite3/session.d.ts`) — **synchronous**, not `Promise<T>`. This is the single most load-bearing fact in this plan; see "Verified transaction behavior" below.
- `SQLiteInsertBase`/select/update/delete builders extend `QueryPromise<T>` — they are lazy and thenable, but **do not execute until consumed**. Calling `.returning()` alone and discarding the result runs nothing at all (verified empirically, see below). The synchronous terminal methods are `.all()`, `.get()`, `.run()`.
- `inArray` is exported from `drizzle-orm`'s top level (`node_modules/drizzle-orm/index.d.ts` re-exports it from `sql/expressions/conditions.d.ts`), same import path already used for `eq`/`ne` in Phase 2's tests.
- `zod` 4.4.3's `z.object({...}).strict()`, `z.enum([...])`, `z.array(...)`, `.safeParse()` all behave exactly as documented — spot-checked with a throwaway script against the installed package.
- `REQUIREMENT_CATEGORIES` (`src/db/schema/canonical.ts`) includes `gpa`, `test`, `shadowing`, `other` — all four categories this plan needs. `DEADLINE_TYPES` includes `rolling` and `unknown` — both this plan needs; it does **not** include a `closed` member, which is why Vanderbilt's closure is modeled as `deadline_type='unknown'` plus an explanatory claim, per `docs/research-workflow.md` §8's explicit instruction.
- `programs.classSize`, `applicationCycles.deadlineDate`, `requirements.valueNumber`/`valueBool`/`valueText`, `schools.city`/`state` are all nullable columns (confirmed by reading `src/db/schema/canonical.ts` directly) — each can genuinely hold NULL for an unresearched fact. `tuitionEstimates.residency`/`amountCents`/`covers` are **NOT NULL** with no nullable "unknown" path — see the ruling below for why this plan never inserts into `tuition_estimates`.

### Verified transaction behavior — a footgun, confirmed empirically

Ran a throwaway script (`tsx`, against a real migrated temp DB, deleted after) exercising four patterns:

1. `db.transaction((tx) => { tx.insert(...).returning(); return "x"; })` — the insert is **never executed**. Zero rows land. `.returning()` alone, unconsumed, does nothing.
2. `db.transaction((tx) => { tx.insert(...).returning().all(); ... })` — works correctly. The row is inserted and committed.
3. `db.transaction(async (tx) => { await tx.insert(...).returning(); ... })` — better-sqlite3 detects the callback returned a promise and **throws** `"Transaction function cannot return a promise"`. But the insert **still landed in the database** (confirmed by querying afterward) — the `await` triggered execution before the synchronous wrapper had a chance to reject it, so the write leaked through **outside any transactional guarantee**, despite the call site receiving what looks like a failure. This is silent, dangerous, and exactly the shape of bug `docs/plan.md`'s "no `--partial` mode... a half-applied research bundle is worse than no bundle" rule exists to prevent.
4. `db.transaction((tx) => { tx.insert(...).returning().all(); throw new Error("x"); })` — the row is correctly rolled back. Throwing inside a synchronous callback is the only correct way to abort.

**Binding rule for this plan:** every function passed to `db.transaction(...)`, and everything it calls, must be plain (non-`async`) and must terminate every Drizzle statement with `.all()`, `.get()`, or `.run()` — never bare `.returning()`, never `await`. The pre-transaction existence check (ordinary `db.select()...` outside any transaction) is fine to leave as a normal synchronous call via `.all()` too, for consistency, even though it isn't itself inside a transaction.

## Known spec ambiguities — flagged, not silently resolved

1. **Baylor/Texas Heart: "resolve the duplicate" vs. "23 programs exist."** `docs/research-workflow.md` §8 says to "decide whether Baylor is a separate program or an affiliation of THI, then record it once" (implying a merge to 22). `docs/plan.md`'s Phase 2.5 gate says "23 programs exist" (implying no merge). These conflict. **Ruling:** keep 23 distinct `programs` rows — the gate is the more specific, testable acceptance criterion, and creating two flagged, cross-referenced rows is reversible (either can be archived later once a human resolves it) whereas a silent merge at import time is not easily undone without re-deriving which one "should have" existed. Baylor's program gets one extra `claims` row (`subjectTable='programs'`, `fieldKey='duplicate_check'`, `state='unknown'`) explaining the overlap and pointing at Texas Heart Institute by name, so `/verify` surfaces it for a human decision later. Cost if wrong: an admin later archives one of the two rows — a single `UPDATE`, not a schema change.
2. **`tuition_estimates` has no nullable "unknown" path.** `residency`, `amount_cents`, and `covers` are all `NOT NULL`, so this table cannot represent "the tuition is not yet properly sourced" the way `requirements.value_number` can (nullable). **Ruling:** this import never inserts into `tuition_estimates`. The legacy tuition figure is instead parked as a `requirements` row (`category='other'`, `label='Tuition (unit and residency tier not yet determined)'`, `value_number=NULL`) with a `state='unknown'` claim carrying the raw figure. Once a researcher determines the real residency tier and what the number covers, it gets promoted into a proper `tuition_estimates` row by hand (or by a later phase) — this import does not guess. Cost if wrong: 23 `requirements` rows get manually re-entered as `tuition_estimates` rows instead of a smaller migration — no data is lost either way, since the claim note preserves the original figure.
3. **Which fields count as "known."** The spec text says "name, city, credential, and URL." This plan reads "city" as the full parsed location (`city` + `state`, both directly stated in the same source string, e.g. `"Glendale, AZ"`) and reads "URL" as `programs.website_url` specifically (the program's admissions page), not `schools.website_url` (which stays NULL/unclaimed — the legacy corpus never states a general school homepage, only the specific program page). `programs.name` (an internally-generated label like `"MS in Cardiovascular Perfusion"`) is **not** treated as a sourced claim — it's this app's own naming convention, not text read from a source.
4. **No legacy deadline string is valid for the cycle this import creates.** The corpus was captured for the 2025-26 cycle; this import creates 2026-27 `application_cycles` rows. Even the two fully-specified dates (Baylor's `"July 1 2025"`, UTHealth's `"July 15 2026"`) describe last cycle, not this one. **Ruling:** `application_cycles.deadline_date` stays NULL for all 23 rows, `deadline_type` defaults to `'unknown'` except University of Utah (`'rolling'`, directly and unambiguously stated by the source, not a guess), and every raw deadline string is preserved verbatim in a `claims.note` hint. This is a stricter reading than "use the date if it looks well-formed" — deliberately so, since a well-formed date from the wrong cycle is more dangerous than an obviously-missing one (it looks trustworthy and isn't).
5. **`import_batches`/`change_log` are not written by this script.** Those tables exist (Phase 2) but their active use is scoped to Phase 5 (`change_log` on every canonical mutation) and Phase 6 (`import_batches` for the general `scripts/import.ts` pipeline). This one-time legacy migration predates both and does not integrate with the audit trail yet.

```ts
export function slugify(input: string): string {
  return input
    .toLowerCase()
    .normalize("NFKD")
    .replace(/[̀-ͯ]/g, "")
    .replace(/[^a-z0-9]+/g, "-")
    .replace(/^-+|-+$/g, "");
}
```

```ts
import { z } from "zod";

export const legacyRawRecordSchema = z
  .object({
    name: z.string().min(1),
    city: z.string().min(1),
    degree: z.string().min(1),
    deadline: z.string().min(1),
    gpa: z.number(),
    gre: z.string(),
    tuition: z.number(),
    classSize: z.number().int(),
    lat: z.number(),
    lng: z.number(),
    url: z.string().url(),
    prereqs: z.array(z.string()),
    notes: z.string().optional(),
  })
  .strict();

export const legacyRecordSchema = z
  .object({
    raw: legacyRawRecordSchema,
    triage: z.array(z.string()),
  })
  .strict();

export const legacyCaptureSchema = z
  .object({
    format: z.string(),
    captured_at: z.string(),
    origin: z
      .object({
        app: z.string(),
        repo: z.string(),
        commit: z.string(),
        file: z.string(),
        exported_symbol: z.string(),
      })
      .strict(),
    import_policy: z
      .object({
        verification: z.string(),
        locked: z.boolean(),
        claim_state: z.string(),
        checked_at: z.null(),
        rationale: z.string(),
      })
      .strict(),
    known_issues: z.array(z.string()),
    record_count: z.number().int(),
    records: z.array(legacyRecordSchema),
  })
  .strict();

export type LegacyCapture = z.infer<typeof legacyCaptureSchema>;
export type LegacyRecord = z.infer<typeof legacyRecordSchema>;
```

```ts
import { REQUIREMENT_CATEGORIES } from "@/db/schema/canonical";
import { slugify } from "@/lib/slug";
import type { LegacyRecord } from "./schema";

export type Credential = "MS" | "MPS" | "MHS" | "BS" | "Certificate" | "Other";
type RequirementCategory = (typeof REQUIREMENT_CATEGORIES)[number];

export function normalizeCredential(raw: string): Credential {
  switch (raw) {
    case "MS":
      return "MS";
    case "MHS":
      return "MHS";
    case "MPS":
      return "MPS";
    case "Cert":
    case "Certificate":
    case "Certificate (via THI)":
      return "Certificate";
    default:
      throw new Error(`Unrecognized legacy credential spelling: "${raw}"`);
  }
}

export function parseCityState(raw: string): { city: string; state: string } {
  const lastComma = raw.lastIndexOf(",");
  if (lastComma === -1) {
    throw new Error(`Expected "City, ST" format, got: "${raw}"`);
  }
  const city = raw.slice(0, lastComma).trim();
  const state = raw.slice(lastComma + 1).trim();
  if (!/^[A-Z]{2}$/.test(state)) {
    throw new Error(`Expected a 2-letter state code, got "${state}" from "${raw}"`);
  }
  return { city, state };
}

  legacyKey: string;
  school: { slug: string; name: string; city: string; state: string };

    slug: string;

export function buildProgramImportPlan(record: LegacyRecord): ProgramImportPlan {
  const { raw } = record;
  const credential = normalizeCredential(raw.degree);
  const { city, state } = parseCityState(raw.city);
  const special = SPECIAL_CASES[raw.name] ?? {};

  const requirements: ProgramImportPlan["requirements"] = [
    {
      category: "gpa",
      label: "Minimum overall GPA",
      unit: "gpa",
      claimNote: `legacy 2025-26 dashboard said ${raw.gpa}`,
    },
    {
      category: "test",
      label: "GRE required",
      unit: null,
      claimNote: `legacy 2025-26 dashboard said: GRE required = ${raw.gre}`,
    },
    {
      category: "other",
      label: "Tuition (unit and residency tier not yet determined)",
      unit: null,
      claimNote: `legacy 2025-26 dashboard said tuition = ${raw.tuition}; unit (total/per-year/per-credit) and residency tier undetermined`,
    },
  ];

  if (special.shadowingFromNotes && raw.notes) {
    requirements.push({
      category: "shadowing",
      label: "Observation / shadowing hours",
      unit: null,
      claimNote: `legacy 2025-26 dashboard notes: "${raw.notes}"`,
    });
  }

  return {
    legacyKey: raw.name,
    school: { slug: slugify(raw.name), name: raw.name, city, state },
    program: {
      slug: `perfusion-${credential.toLowerCase()}`,
      name: `${credential} in Cardiovascular Perfusion`,
      credential,
      latitude: raw.lat,
      longitude: raw.lng,
      websiteUrl: raw.url,
    },
    cycle: {
      cycleLabel: CYCLE_LABEL,
      entryYear: CYCLE_ENTRY_YEAR,
      deadlineType: special.deadlineType ?? "unknown",
    },
    source: {
      url: raw.url,
      notes:
        "URL carried over from the 2025-26 legacy capture (seed/legacy/2025-26-aistudio.json); not yet freshly fetched by this app.",
    },
    knownClaims: [
      { subject: "school", fieldKey: "name" },
      { subject: "school", fieldKey: "city" },
      { subject: "school", fieldKey: "state" },
      { subject: "program", fieldKey: "credential" },
      { subject: "program", fieldKey: "website_url" },
    ],
    requirements,
    prerequisites: raw.prereqs,
    unknownClaims: [
      {
        subject: "program",
        fieldKey: "class_size",
        note: `legacy 2025-26 dashboard said classSize = ${raw.classSize}`,
      },
      {
        subject: "cycle",
        fieldKey: "deadline_date",
        note: `legacy 2025-26 dashboard said: "${raw.deadline}" (describes the 2025-26 cycle; not valid for the 2026-27 cycle without re-sourcing)`,
      },
      ...(special.extraUnknownClaims ?? []),
    ],
  };
}

export function buildImportPlan(records: LegacyRecord[]): ProgramImportPlan[] {
  return records.map(buildProgramImportPlan);
}
```

```ts
import { inArray } from "drizzle-orm";
import type { BetterSQLite3Database } from "drizzle-orm/better-sqlite3";
import * as schema from "@/db/schema";
import type { ProgramImportPlan } from "./transform";

export type ImportMode = "dry_run" | "apply";

export interface ImportReportLine {
  action: "CREATE" | "SKIP";
  kind: "program";
  label: string;
}

export interface ImportReport {
  lines: ImportReportLine[];
  created: {
    schools: number;
    programs: number;
    sources: number;
    requirements: number;
    prerequisites: number;
    claims: number;
  };
  skipped: number;
}

class DryRunRollback extends Error {}

const REQUIREMENT_VALUE_FIELD: Record<string, string> = {
  gpa: "value_number",
  test: "value_bool",
  other: "value_number",
  shadowing: "value_text",
};

export function runLegacyImport(
  db: BetterSQLite3Database<typeof schema>,
  plans: ProgramImportPlan[],
  mode: ImportMode,
): ImportReport {
  const existingKeys = new Set(
    db
      .select({ legacyKey: schema.programs.legacyKey })
      .from(schema.programs)
      .where(
        inArray(
          schema.programs.legacyKey,
          plans.map((p) => p.legacyKey),
        ),
      )
      .all()
      .map((row) => row.legacyKey),
  );

  const report: ImportReport = {
    lines: [],
    created: { schools: 0, programs: 0, sources: 0, requirements: 0, prerequisites: 0, claims: 0 },
    skipped: 0,
  };

  const applyAll = (tx: BetterSQLite3Database<typeof schema>): void => {
    for (const plan of plans) {
      if (existingKeys.has(plan.legacyKey)) {
        report.lines.push({
          action: "SKIP",
          kind: "program",
          label: `${plan.school.slug}/${plan.program.slug} (legacy_key="${plan.legacyKey}")`,
        });
        report.skipped += 1;
        continue;
      }

      const [school] = tx
        .insert(schema.schools)
        .values({
          slug: plan.school.slug,
          name: plan.school.name,
          city: plan.school.city,
          state: plan.school.state,
        })
        .returning()
        .all();
      report.created.schools += 1;

      const [program] = tx
        .insert(schema.programs)
        .values({
          schoolId: school!.id,
          slug: plan.program.slug,
          name: plan.program.name,
          legacyKey: plan.legacyKey,
          credential: plan.program.credential,
          websiteUrl: plan.program.websiteUrl,
          latitude: plan.program.latitude,
          longitude: plan.program.longitude,
        })
        .returning()
        .all();
      report.created.programs += 1;

      const [cycle] = tx
        .insert(schema.applicationCycles)
        .values({
          programId: program!.id,
          cycleLabel: plan.cycle.cycleLabel,
          entryYear: plan.cycle.entryYear,
          deadlineType: plan.cycle.deadlineType,
        })
        .returning()
        .all();

      const [source] = tx
        .insert(schema.sources)
        .values({ url: plan.source.url, sourceType: "program_site", notes: plan.source.notes })
        .returning()
        .all();
      report.created.sources += 1;

      for (const kc of plan.knownClaims) {
        const subjectTable = kc.subject === "school" ? "schools" : "programs";
        const subjectId = kc.subject === "school" ? school!.id : program!.id;
        tx.insert(schema.claims)
          .values({
            subjectTable,
            subjectId,
            fieldKey: kc.fieldKey,
            state: "known",
            sourceId: source!.id,
          })
          .run();
        report.created.claims += 1;
      }

      for (const req of plan.requirements) {
        const [reqRow] = tx
          .insert(schema.requirements)
          .values({ cycleId: cycle!.id, category: req.category, label: req.label, unit: req.unit })
          .returning()
          .all();
        report.created.requirements += 1;

        tx.insert(schema.claims)
          .values({
            subjectTable: "requirements",
            subjectId: reqRow!.id,
            fieldKey: REQUIREMENT_VALUE_FIELD[req.category]!,
            state: "unknown",
            sourceId: source!.id,
            note: req.claimNote,
          })
          .run();
        report.created.claims += 1;
      }

      plan.prerequisites.forEach((subject, index) => {
        tx.insert(schema.prerequisiteCourses)
          .values({
            cycleId: cycle!.id,
            subject,
            notes:
              "Unstructured legacy prerequisite name — needs credits/lab/min-grade/recency research (docs/research-workflow.md §8).",
            sortOrder: index,
          })
          .run();
        report.created.prerequisites += 1;
      });

      for (const uc of plan.unknownClaims) {
        const subjectTable = uc.subject === "cycle" ? "application_cycles" : "programs";
        const subjectId = uc.subject === "cycle" ? cycle!.id : program!.id;
        tx.insert(schema.claims)
          .values({
            subjectTable,
            subjectId,
            fieldKey: uc.fieldKey,
            state: "unknown",
            sourceId: source!.id,
            note: uc.note,
          })
          .run();
        report.created.claims += 1;
      }

      report.lines.push({
        action: "CREATE",
        kind: "program",
        label: `${plan.school.slug}/${plan.program.slug} (legacy_key="${plan.legacyKey}")`,
      });
    }

    if (mode === "dry_run") {
      throw new DryRunRollback();
    }
  };

  try {
    db.transaction(applyAll);
  } catch (error) {
    if (!(error instanceof DryRunRollback)) {
      throw error;
    }
  }

  return report;
}
```
